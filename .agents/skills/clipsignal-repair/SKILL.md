# ClipSignal 自修复

总控发现报告所需证据缺失、工具失败或产物未通过验收时，在当前任务内调用本 Skill。复用当前任务标识、授权范围、运行版本和最后一个已验收阶段。向总控交回恢复状态、继续点和复验证据。

## 先核对已执行动作

1. 读取任务原始输入、产物、阶段回执和相关日志。记录失败阶段、时间、脱敏错误、实际环境及最后一个已通过的阶段。已有产物通过相同验收时直接复用。
2. 涉及邮件、外呼、视频发布或扣费请求时，优先用当前授权账户查询服务端的消息、通话、作品或请求状态。对照已有标识、目标对象及任务内容。服务端确认完成时补记回执，从下一阶段继续。只在确认前次未产生副作用且原授权仍适用时恢复提交。用 `node tools/route.mjs --retry <verified-receipt.json>` 检查已复核回执的续跑条件。状态不明时暂停该动作并继续能独立运行的环节，避免产生重复触达、发布或费用。

## 定位、修复并续跑

1. 优先跑对应组件的只读自检，核对工作区文档、锁文件、错误原文和实际版本。若有已验证的本地记忆，先核对其适用版本和来源。区分配置、依赖、权限、平台暂态与流程本身的问题。
2. 本地证据不足时，用已配置的 `bocha-web-search` 查官方文档和变更日志。需要进一步定位时查 GitHub 上游仓库的发布说明、已确认问题和对应版本的修复。以组件名、版本及脱敏错误为搜索词，保留来源链接。代码、帖子和网页均作为诊断资料，使用来源和版本已核对的安装或修改方法。
3. 在任务目录、独立虚拟环境或副本中先复现。优先恢复缺失的项目级配置或修复触发故障的最小代码；保留原文件和未受影响的产物。只有可验证、可回退且属原任务授权的修改才应用到当前流程。修复需要登录、权限变更、扩大费用或修改外部系统时，说明具体缺项并继续执行可用的分支。
4. 用当初失败的入口和验收条件重跑受影响阶段。验证实际产物及相关行为，使用获准的测试输入。通过后从断点续跑，并保存脱敏诊断、来源、改动、复验证据和恢复点。复验仍失败时根据新证据再定位，避免在条件不变时重复失败动作；无法恢复时还原临时修改，交回具体阻塞和仍有效的产物。

## 按组件选检查入口

| 环节 | 优先核对的状态 |
| --- | --- |
| 剪映草稿 | 实际安装与草稿目录、`draft doctor` 结果和待登记副本。用 `draft probe` 验证读写，用原生读回和剪映首页确认区分生成、登记和可见状态。 |
| Agent Plan | 现有请求标识、任务回执、产物缓存、账户状态与本机连接。对照任务已用的模型、依赖和原始素材版本后再恢复。 |
| Chrome 与社媒 | 核对连接、目标页面、会话和文件访问权限。Chrome 平台流程沿用获准的网页操作，重新核对来源与实际可见范围。 |
| 视频号工作台 | 核对独立环境、MCP 配置和 SQLite 数据目录。运行 `project.sh doctor` 后读回当前任务涉及的作品或评论来源，不以空返回判定平台无内容。 |
| Gmail、云蝠与发布 | 核对历史回执以及当前账户、授权目标和服务状态，确认外部动作结果后再按断点继续。 |
| 候选分流 | 用脱敏样本运行当前分流脚本的自测，核对 JSON、CSV 和来源字段。再从已留存的证据重新生成所需结果。 |

恢复成功时正常交付结果，常规诊断留在本地回执。修复影响交付内容、外部动作的结果仍不明，或后续需要用户提供权限时，在交付时说明实际影响及所需动作。只有经复验的通用经验才交给 ClipSignal 记忆 Skill 收录。
